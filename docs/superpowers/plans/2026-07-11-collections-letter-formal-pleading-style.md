# Collections Letter Templates — Formal Legal-Pleading Style Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the personal-letter framing (date/addressee/RE line/"Dear Name," salutation) in both the Equipment Agreement and Employment Agreement PDF generators with a formal contract caption block and recital, switch body typography to Times New Roman, and give every numbered clause a true hanging indent.

**Architecture:** Both documents are generated by two independent IPC handlers in `src/main/ipc/index.ts` (`employee:generate-equipment-agreement`, `employee:generate-employee-agreement`), each building an HTML string via a template literal with its own inline `<style>` block. All changes are edits within these two handlers plus a light-touch check of one small shared helper function (`agreementSignatureBlock`) — no new files, no new IPC channels, no schema changes.

**Tech Stack:** TypeScript (Electron main process), inline HTML/CSS template literals.

- [ ] **Step 2: Replace the letter-framing markup with the caption block + recital**

Find:

```html
  <!-- Date -->
  <div class="letter-date">${signatures?.employee?.date
    ? fmtDate(String(signatures.employee.date).length === 10 ? signatures.employee.date + 'T12:00:00' : signatures.employee.date)
    : today}</div>

  <!-- Addressee -->
  <div class="addressee">
    ${empName}<br/>
    ${empTitle ? esc(empTitle) + '<br/>' : ''}
    ${empAddr ? esc(empAddr) + '<br/>' : ''}
  </div>

  <!-- RE line -->
  <div class="re-line">RE: Employer Provided Equipment Agreement</div>

  <!-- Salutation -->
  <div class="salutation">Dear ${empName.split(' ')[0] || empName},</div>

  <!-- Body opening -->
  <div class="letter-body">
    <p>This letter constitutes a formal agreement between ${companyName} ("Employer") and ${empName} ("Employee"), effective as of ${empStart || today}, regarding the issuance, use, care, and return of company-owned equipment. By acknowledging this document, the Employee agrees to the terms and conditions set forth herein.</p>
  </div>
```

Replace with:

```html
  <!-- Caption block -->
  <div class="caption-block">
    <p class="caption-title">Employer Provided Equipment Agreement</p>
    <p class="caption-parties">Between ${companyName} and ${empName}</p>
    <p class="caption-date">Effective ${signatures?.employee?.date
      ? fmtDate(String(signatures.employee.date).length === 10 ? signatures.employee.date + 'T12:00:00' : signatures.employee.date)
      : (empStart || today)}</p>
  </div>

  <!-- Body opening: contract recital -->
  <div class="letter-body">
    <p>This Agreement is made and entered into as of ${empStart || today}, by and between ${companyName} ("Employer") and ${empName}${empTitle ? `, ${empTitle}` : ''}${empAddr ? `, of ${esc(empAddr)}` : ''} ("Employee"), regarding the issuance, use, care, and return of company-owned equipment (this "Agreement"). The parties agree as follows:</p>
  </div>
```

Escaping is confirmed (verified directly in this file, not left to guesswork): at the top of this handler, `const empTitle = esc(employee.job_title || '');` — already escaped, so interpolate `empTitle` BARE (no `esc()` call) as shown above. `const empAddr = [...].filter(Boolean).join(', ');` — NOT escaped (raw string concatenation), so it MUST be wrapped in `esc(empAddr)` as shown above. Getting this backwards is either a double-escape display bug (literal `&amp;amp;` visible in the PDF) or an HTML-injection risk (unescaped employee address data rendered directly into HTML).
